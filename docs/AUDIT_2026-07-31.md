# Auditoría correctiva completa

Fecha: 31 de julio de 2026.

Alcance: shell macOS SwiftUI, estado y persistencia SQLite, capturas,
supervisión ActivityWatch, compartición HTTP, informes, backups, scripts de
build y proceso de distribución. La revisión cubre el código propio de Chosky;
los submódulos upstream de ActivityWatch se tratan como dependencias fijadas.

## Resultado

La revisión estática y automatizada no deja fallos reproducibles abiertos en
las rutas cubiertas por las pruebas. Se corrigieron los siguientes defectos:

### Privacidad y seguridad

- el modo estricto podía reactivar watchers al reiniciar ActivityWatch durante
  una pausa o si la pausa ocurría mientras arrancaba el servidor;
- cambiar el modo continuo no arrancaba o detenía los watchers de inmediato;
- una captura ya iniciada podía persistirse después de pausar, finalizar o
  cambiar de sesión;
- el panel compartido mostraba sesiones activas aunque se hubiese desactivado
  el permiso de cronómetro, y `oldHistory`/`todaySummary` no filtraban datos;
- el servidor interpretaba fragmentos TCP como peticiones HTTP completas;
- un fallo de auditoría al habilitar la compartición podía dejar el listener
  ocupando el puerto, y la caducidad no cerraba el acceso automáticamente;
- el CSV aceptaba prefijos de fórmula en descripciones controladas por usuario;
- el JSON podía incluir tarifas aunque `includeRates` fuese falso;
- los permisos 0700/0600 no se reafirmaban sobre directorios o logs existentes.

### Integridad y ciclo de vida

- recargar catálogos o capturas durante una sesión viva podía marcarla como
  recuperación de cierre incompleto;
- pausar, finalizar o cambiar de estado podía descartar el último intervalo de
  tiempo calculado por trabajar con una copia anterior al `tick`;
- cliente, proyecto y tarea podían combinarse aunque no perteneciesen a la
  misma relación lógica;
- la detección AFK estaba modelada pero nunca se activaba; ahora usa la
  inactividad de entrada local y vuelve a `running` al detectar actividad;
- un fallo intermedio al mover una captura a la papelera podía dejar archivos y
  base de datos en estados distintos;
- el guardián podía dejar huérfano un auxiliar que ignorase `SIGTERM`, y tenía
  una carrera si la señal llegaba justo después de crear el hijo;
- el cierre de la aplicación programaba el cleanup de forma asíncrona, con
  riesgo de que el proceso terminase antes del checkpoint y la revocación;
- la restauración de backup migraba el SQLite extraído antes de validarlo, lo
  que podía convertir un archivo incompleto en una aparente restauración sana;
- los backups con capturas omitían las miniaturas.

### Función, exportación y build

- los informes omitían sesiones que empezaban antes del rango pero lo
  atravesaban, aceptaban rangos invertidos y podían dejar exportaciones
  parciales;
- el PDF usaba un color dinámico que podía quedar blanco sobre fondo claro;
- la exportación combinaba escritura atómica con una opción de protección de
  archivo no fiable en macOS y podía fallar con `EPERM` en temporales;
- el resumen ejecutivo no llegaba al PDF;
- el botón de barra de menú no reabría la ventana principal;
- el selector de proyecto no actualizaba el valor facturable y el control de
  hora aproximada de captura no mostraba ninguna hora;
- los intervalos mínimo/máximo de captura podían quedar incoherentes;
- la base incremental `.build/build.db` fallaba con I/O dentro del proveedor de
  archivos; los builds de auditoría usan ahora un scratch temporal;
- los ejecutables de prueba compartían el cache global de módulos de Clang y
  podían interferirse si se compilaban simultáneamente.

## Verificación automatizada

```bash
make chosky-test
```

- 8 pruebas nativas: estado, migración/seed, sesión única, capturas, relaciones,
  persistencia temporal, AFK, exportación y restauración;
- 8 comprobaciones ActivityWatch: servidor, dos watchers, buckets, pausa
  estricta, reinicio pausado, modo continuo, pausa durante arranque y cierre;
- 3 comprobaciones de compartición: listener/token, permisos efectivos y
  revocación.

También se completaron:

- build release de los dos ejecutables Swift;
- bundle arm64 con firma ad hoc válida en staging;
- DMG generado, verificado, montado y con firma interna válida;
- prueba de fallo del guardián contra un hijo que ignora `SIGTERM`;
- validación del manifiesto Swift y sintaxis de todos los scripts Bash;
- escaneo local de patrones de secretos, sin credenciales detectadas.

## Riesgo residual y pruebas físicas pendientes

No se convierten en aprobadas las pruebas que requieren hardware, TCC o una
segunda máquina: captura real y revocación de permiso, bloqueo/reposo/tapa,
dos monitores, disco lleno, VoiceOver, LAN desde otro dispositivo y una jornada
larga. Continúan además las limitaciones documentadas: ActivityWatch arm64
beta, panel LAN HTTP sin TLS, backup sin cifrado, firma ad hoc no notarizada y
funciones v0.1 todavía no implementadas. Los toggles de compartición que aún no
publican capturas, títulos, tarifas o descargas quedan deshabilitados para no
crear una falsa expectativa.

El proveedor de archivos de la carpeta Documents puede volver a añadir
`com.apple.FinderInfo` al `.app` copiado y hacer fallar una verificación
posterior de `codesign`. La copia de staging se limpia y verifica; para entrega
se debe preferir el DMG verificado, que conserva el bundle sin ese atributo.
